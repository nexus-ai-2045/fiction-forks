# ビジュアルシステム

## 目的

Fiction Forksの図は、雰囲気を飾るためではなく、次の4点を一目で区別するために使う。

1. 現在から続く基準世界線
2. 修復不能条件へ入った状態
3. フィクション・レンズから生まれた介入世界線
4. 介入を発動させる技術・制度・運用の依存関係

READMEは最初のプレイ画面として扱う。初見の人が30秒で「何もしないと2036年に修復不能」「介入は技術ツリーを要する」「一つのPRが一つの世界線」と説明できることを優先する。

## 視覚文法

| 要素 | 形 | 色 | 必須ラベル |
|---|---|---|---|
| 基準世界 | 一本の直線 | 無彩色 | `BASELINE`または「無介入」 |
| 介入世界 | 基準線から分かれる曲線 | 青から青緑 | `ALTERNATIVE`または「介入」 |
| 修復不能 | 菱形または明確な停止記号 | コーラル | `REPAIRABILITY LOST`または「修復不能」 |
| 技術ノード | 角丸矩形 | 青 | `TECHNOLOGY`と日本語説明 |
| 制度ノード | 角丸矩形 | 青 | `INSTITUTION`と日本語説明 |
| 運用ノード | 角丸矩形 | 青緑 | `OPERATIONS`と日本語説明 |
| 未確定仮説 | 破線 | 中間色 | 「仮説」または状態名 |

色だけでは意味を伝えない。形、位置、英語の短い識別子、日本語の説明を併用する。破滅は赤い演出ではなく、判定名と発生年を必ず表示する。

| token | value | 用途 |
|---|---|---|
| `canvas` | `#07111F` | 図の背景 |

| `text-muted` | `#A9BBCA` | 補足説明 |
| `baseline` | `#7F91A3` | 無介入世界線 |
| `intervention` | `#56CCF2` | 分岐と技術・制度 |
| `repair` | `#63E6BE` | 実装済み介入と別の未来 |

SVGはsystem fontを使い、外部font、script、埋め込み画像、外部参照を含めない。GitHubのlight/dark themeのどちらでも図自体のコントラストを維持する。

## READMEの情報階層

1. 一文の約束: フィクションの部品で日本の未来をforkする
2. ヒーロー図: 2026、無介入2036、介入分岐、実装ツリー
3. 三つの動詞: 読む、実行する、forkする
4. 現在遊べる一つの世界と比較結果
5. クイックスタート
6. 新しい世界線を追加する参加契約
7. 根拠、権利、安全、SSOT

詳細なルールをヒーローへ詰め込まない。正確な数値、反証条件、CLI、権利境界は本文と正本文書へ置く。

## フィクションIPの扱い

作品名は共通言語レンズとして本文中で参照できる。公式画像、漫画コマ、キャラクター造形、台詞、ロゴ、特徴的な装飾を視覚素材として再利用しない。プロジェクトの図はすべて、時間軸、依存関係、状態比較という独自の情報表現にする。

これにより、作品を知る人には入口が分かり、作品を知らない人にも図の意味が成立する。非公式プロジェクトであることと第三者IPへMIT Licenseが及ばないことは、READMEと`THIRD_PARTY_NOTICES.md`で明示する。

## 派生物と正本

`assets/readme/hero.svg`はこの文書の視覚文法から作る派生物であり、シナリオの数値や判定を所有しない。年、破滅条件、介入結果が変わる場合はscenarioとsimulation contractを先に変更し、図の表示を追従させる。

Figma、画像生成モック、Web UI、動画、発表スライドも派生物である。画面上の数値と結果はengine出力へ一致させ、独自の予測値を追加しない。
