# ADR 0007: READMEを最初のプレイ画面として設計する

- Status: Accepted
- Date: 2026-08-24

## Context

現在のMVPはCLIで実行できるが、GitHubを訪れた人は実行前に、世界の危機、介入方法、参加単位を理解する必要がある。文章だけではゲームの分岐構造が伝わりにくく、作品の公式素材を使うと非公式プロジェクトと第三者IPの境界も曖昧になる。

## Decision

READMEを単なる導入文書ではなく、最初のプレイ画面として設計する。

- 冒頭で2026年から2036年への基準世界線と介入世界線を同時に見せる。
- 「読む、実行する、forkする」を最初の三つの行動として固定する。
- オリジナルSVGとMermaidだけを使用し、作品の公式画像、キャラクター、ロゴ、台詞を視覚素材にしない。
- SVGは状態や意味を色だけに依存せず、形とラベルを併用する。
- READMEの図は表示層であり、scenario、engine、simulation contractの値を上書きしない。

視覚文法とtokenは [ビジュアルシステム](../visual-system.md) を正本とする。

## Consequences

- GitHubだけでプロジェクトのコアループと参加方法を説明できる。
- Web UIが未実装でも、体験の入口をレビューできる。
- 静的SVGに年や状態を含めるため、simulation contract変更時には追従確認が必要になる。
- 作品名による分かりやすさは本文で維持しつつ、公式提携と誤認される視覚表現を避けられる。

## Alternatives considered

- 文章と表だけにする: 正確だが、世界線の分岐を短時間で把握しにくいため不採用。
- 作品の公式画像やキャラクターをヒーローに使う: 権利と公認誤認の境界が広がるため不採用。
- 生成画像だけを使う: 情報の正確性、編集性、アクセシビリティ、差分reviewが弱いため主図には採用しない。
- Webアプリ完成まで視覚設計を待つ: 参加入口の改善が遅れるため不採用。

## 見直し条件

Web版の第一画面が実装され、READMEより正確かつ低摩擦な体験入口を提供できたとき、READMEの役割と図の情報量を見直す。
